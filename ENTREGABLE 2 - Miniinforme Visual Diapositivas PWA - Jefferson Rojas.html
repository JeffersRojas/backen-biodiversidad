🔄 Estrategia de Actualización

skipWaiting() · clients.claim()

⚡ self.skipWaiting() · Línea 21 + mensaje línea 38

Sin esta llamada el worker nuevo se quedaría días en estado waiting hasta cerrar todas las pestañas (horas/días para biólogos en campo).

Con skipWaiting: se activa inmediatamente después del install SIN esperar.


// INSTALL evento
caches.open(CACHE_APP_SHELL)
  .then(c => c.addAll(APP_SHELL))
  .then(() => self.skipWaiting());

👥 self.clients.claim() · Línea 32

Hace que el worker recién activado intercepte peticiones YA de pestañas abiertas (sin reload del usuario).

Sin claim: el usuario tendría que pulsar F5 después de cada actualización para que el nuevo SW entre en acción.


// ACTIVATE evento
caches.keys().then(keys =>
  Promise.all(keys.filter(...).map(caches.delete))
  .then(() => self.clients.claim());
⚠ Trade-off: posible mismatch JS viejos piden recursos nuevos. Se mitiga con SWR ✅ Estrategia versionado nombres: cambiar -v1 → -v2 limpia caché ✅ updatefound event en app.js → toast "Nueva versión disponible"

🚀 Estrategia de Caché Aplicada

🥇 Network First

HTML navegaciones · index.html, / , offline.html.

¿Por qué?

HTML quiero siempre el más actualizado; si no hay red → offline.html como último recurso.

🥈 Stale-While-Revalidate

App Shell core: styles.css, app.js, api.js, router.js, db.js, sync.js, imageCompress.js, manifest.json.

¿Por qué?

Mostrar cacheado 0 ms, y en paralelo descarga silenciosamente actualizado para próxima visita.

🥉 Cache First

Imágenes / fotos avistamientos, scripts terceros, iconos SVG.

¿Por qué?

Fotos son inmutables. Ahorra 4G rural en Colombia (datos limitados).

🚫 Exception: API REST (/api/*) → NETWORK ONLY con 503 JSON

Auth, fauna, flora, avistamientos y batch NUNCA se cachean. Si no hay red se responde {error: "OFFLINE", status: 503} para que la app detecte offline y guarde localmente en IndexedDB.

🔎 Hallazgos: Accesibilidad y Rendimiento

♿ Accesibilidad

  • OK Tema oscuro con alto contraste ≥ 4.6:1 corporativo verde/blanco — cumple WCAG AA.
  • OK Todos los inputs tienen <label for=""> asociado.
  • OK Botones táctiles ≥ 44px de alto — FAB 64 px.
  • OK html lang="es-CO" correcto para lectores pantalla.
  • ⚠️ Problema detectado: el toast con aria-live="polite" sin etiquetar. Screen reader no anuncian updates sincronización completada.
  • ⚠️ Modal role="dialog" pero sin trap focus. Tabulador puede salir.

🚀 Rendimiento

  • OK Resuelto error NO_FCP inicial. Antes: ∞ s. Después: ~300 ms.
  • OK Cero librerías externas — no jQuery, no React, no Workbox. ~65 KB.
  • OK Imágenes comprimidas cliente 1280×720 75% ~200 KB cada una.
  • OK Scripts defer + registro SW post-idle.
  • ⚠️ Problema detectado: manifest SVG inline: launcher Android versiones antiguas no renderiza data:svg en manifest. Recomendado PNGs archivos.
  • ⚠️ Problema detectado: sin preload crítica estilos.
